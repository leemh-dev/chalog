# 차록 UX/UI 설계 v0.3

2026-11-15 KST · 구현 명세 / 실제 앱 검증 전

## 디자인 방향

**말은 짧게, 기록은 정확하게.** 주행 중에는 상태 한 가지와 현재 질문 하나만 크게 보입니다. 정차 후 기록이 상담 자료로 정리됩니다. 대시보드를 수치와 디버그 텍스트로 채우지 않습니다.

- 시스템 Driving view와 순정 내비는 OS/기존 앱 영역입니다. 차록이 복제하거나 덮어쓰지 않습니다.
- 전체 설계 이미지의 왼쪽 차량/가운데 지도는 관계를 설명하는 도식입니다. 공식 화면 캡처·실제 지도·실시간 차량 값이 아닙니다.
- 우측 앱 패널은 목표 배치 예시입니다. 시스템이 primary에 차록을 열면 그 위치에서 같은 흐름을 제공합니다. 강제 3분할/우측 고정 API를 전제하지 않습니다.
- 한 앱 창이 좁을 때는 상태→질문→종료만 남깁니다. 넓으면 정차 상태에서 타임라인을 나란히 표시합니다. 하단 시스템 GNB/상단 상태바 영역을 앱이 차지하지 않습니다.

## 화면과 전이

| --- | --- | --- | --- |
| 준비 전 | 필요할 때, 그 순간을 남기세요 | 기록 준비 켜기 / 동의 | 사용 가능 필드 확인 및 구독 시작 |

| 저장 실패 | 저장을 마치지 못했어요 | 같은 기록 다시 저장 | 새 session 생성/성공 표시 금지 |
| 상담 카드 | 핸들을 돌릴 때 앞쪽 소음 | 원문 확인 / 내보내기 | 보고서 생성, 선택 범위 일치 |

브라우저 시안은 위 상태를 메모리에서 재현합니다. 시안의 저장·관측·음성은 모두 시뮬레이션이고 실제 DB·마이크·SDK를 사용하지 않습니다.

## 대화 설계

1. **시작:** “차록, 증상 기록해 줘.” → 실제 시작 후 “기록을 시작했어요. 어떤 증상이 있었나요?”
2. **이미 설명한 경우:** “핸들을 돌릴 때 앞쪽에서 덜컥거려요.” → “앞쪽에서 덜컥거리는 증상을 남겼어요.” 같은 질문 반복 없음.
3. **순간 표시:** “지금이야.” → “방금 순간을 표시했어요.” 사용자 진술이라는 출처 유지.
4. **소리가 계속 나는 경우:** “계속 소리가 나요.” → 텍스트 증상만 기록. 원음 수집 미지원이면 한 번만 “소리 설명을 남겼어요. 원음 녹음은 지원하지 않아요.” 실제 녹음처럼 파형을 만들지 않음.
5. **종료:** “기록 종료해 줘.” → “기록을 멈추고 저장할게요.” 완료 이후 별도 결과 안내. 인식 실패/저장 실패는 성공으로 답하지 않음.
6. **상담:** 정차 후 “기록을 정리했어요. 정비 상담 때 보여드릴 수 있어요.” 즉시 원인을 추정하거나 긴급도가 낮다고 판단하지 않음.

Gleo 함수 제안은 START_SYMPTOM_RECORD, ADD_SYMPTOM_NOTE(note, markMoment), END_SYMPTOM_RECORD 3개입니다. 공식 SDK 함수명이 아니라 앱이 정의할 이름입니다. asking은 누락·확인을 위한 짧은 왕복에 사용하고 각 Action을 7초 이내 처리합니다. 장시간 기록/저장은 앱의 세션에서 관리합니다. 7초 내 시작을 확정할 수 없으면 성공을 꾸미지 않고 상태 확인/재시도를 안내합니다.

Gleo가 받은 구조화 parameter는 전체 발화 원문으로 표시하지 않습니다. STT에서 받은 최종 텍스트와 구분합니다. 단순 발화 해석/요약 템플릿으로 먼저 완결하고, 외부 LLM 추가 시 동의·데이터 전송·지연·오류/왜곡 검증을 별도로 설계합니다. Pleos 범용 LLM 제공을 전제하지 않습니다.

Gleo 호출과 앱 자체 STT는 별도 진입 경로입니다. 두 음성 수집기를 동시에 열지 않으며 응답은 Gleo 또는 TTS 중 한 경로만 사용합니다. 문서의 마이크 STT와 실제 기기 성공, PCM 주입 성공을 분리합니다.

## 상태·권한·저장 계약

`IDLE → ARMING → ARMED → RECORDING → FINALIZING → SAVED / SAVE_FAILED`

- 준비 동의는 위치·공유와 분리합니다. 기본 OFF, 사용자가 켠 동안에만 버퍼를 수집합니다. Gleo 시작 시 미준비라면 과거 없음으로 현재부터 기록할지 상태/동의에 맞게 처리합니다.
- 같은 시작 action 반복은 새 세션을 만들지 않습니다. 동일 delivery의 중복과 동일한 문장의 새로운 발화를 구별합니다. 종료/재시도도 기존 session ID에 적용합니다.
- 바탕 화면 이동 시 실행 지속을 지원한다고 가정하지 않습니다. 허용된 background 수집이 실제 검증되기 전에는 앱 비활성/종료를 관측 중단으로 기록합니다. 재실행 시 녹음/수집 자동 재개 없음.
- 권한 철회·SDK 끊김·용량 부족은 공백/중단 이유를 남깁니다. 필드별 sampleTime/receiveTime/source/unit/availability를 보존합니다.
- 임시 버퍼는 최근 60초이며 음성 원음은 포함하지 않습니다. 초기 앱 제안 상한은 시작 후 10분, 세션 payload 10MiB 중 먼저 도달하는 조건입니다. 상한 자동 종료 사유를 표시하고 실제 부하 시험 후 조정합니다. 저장 실패 시 RAM에만 남은 구간의 손실 위험을 알립니다.
- 재시작 시 저장된 checkpoint까지만 복원하며 저장되지 않은 구간을 복구했다고 말하지 않습니다. 상태가 RECORDING인 과거 세션은 중단됨으로 표시하고 사용자 확인 후 열람합니다.
- 날짜 변경과 순서 계산은 분리합니다. monotonic time으로 구간을 자르고 wall time은 표시용으로 보존합니다.
- 차속/기어가 불명확하면 정차로 간주하지 않습니다. 상세/수정/공유/센터선택은 잠급니다. 종료 동작은 운전 제한과 충돌하지 않는 승인된 UI/음성 경로로 검증합니다.

## 상담 카드 정보 위계

상단: 사용자 확인 제목 / 기록 날짜 / 실제 확보 구간.

중단: 사용자 설명 → 순간 표시 → 근처에 실제 수신한 관측 → 관측 공백. 같은 시점으로 보간한 가짜 센서 묶음을 만들지 않습니다. 기어·조향·공조 등 일부 관측만 있으면 그대로 표시합니다.

하단: 원음 미수집 / 원인 미판정 / 위치 공유 여부 / 내보내기. 실제 오류 코드와 고장 원인을 혼동하지 않습니다.

1차 내보내기는 로컬 JSON/읽기 쉬운 보고서 파일입니다. 허용된 공유 앱/전달 경로가 없으면 파일 생성까지만 성공으로 표시합니다. QR 서버를 만들지 않은 상태에서 사용 가능한 QR을 그리지 않습니다. 실제 이름·VIN·전화번호·개인 이동 경로는 공개 시연에 쓰지 않습니다.

## 자동 예약과 내비

첫 제출 버전에는 실제 자동 예약을 넣지 않습니다. 공개 예약 API가 확인되지 않았기 때문입니다. UX 확장안에는 센터→일정→공유 범위→명시적 승인→요청/대기/확정/실패를 구분합니다. TEST 센터 구현 여부는 별도 개발 작업으로 판단하며, 본 시안에는 예약 성공을 연출하지 않습니다.

내비 연결은 예약과 독립입니다. 실제 주소·좌표를 확인한 센터를 선택한 뒤 “지금 길 안내”를 실행합니다. 미래 예약 후 자동으로 현재 경로를 바꾸지 않습니다. 시안은 센터 좌표를 만들지 않고 안내 전 상태까지만 보여줍니다.
