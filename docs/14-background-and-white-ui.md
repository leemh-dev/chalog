# 차록 0.2 · 내비 중심 사용과 흰색 UI

이 문서는 0.2 구현 이력입니다. 사용자 정정 이후의 제품 목표는 [docs/15](15-gleo-background-direction.md)를 우선합니다. 최신 방향은 Gleo로 백그라운드 기록·종료, 현재 내비·음악 유지, 명시적 열기에만 우측 패널 표시입니다. 아래 투명 Activity·화면에서 준비·알림 본문으로 열기는 구현 이력이며 최신 음성 중심 요구를 충족했다고 해석하지 않습니다.

2026-11-15 사용자 요청에 따라 차록은 평소에는 백그라운드에서 기록을 유지하고, 사용자가 앱을 열었을 때 기록·상담 화면을 보여 주도록 변경했습니다. docs/07~09와 기존 디자인 자료는 설계 이력으로 보존합니다. 현재 실행 검증은 docs/11을 따릅니다.

## 화면과 동선

- 흰 바탕, 짙은 녹색 주요 동작, 밝은 회색 정보 카드로 앱과 아이콘을 통일합니다. 기록·보관함, 큰 상태 제목, 준비 구간·관측 수, 순간 표시와 종료 버튼의 우선순위를 구분합니다.
- 입력 선택과 TEST 도구는 접힌 설정에 둡니다. TEST 출처는 기록 화면·알림·상담 자료에 유지합니다. 저장된 TEST 기록을 Pleos 입력 화면에서 복원해도 TEST 배지를 표시합니다.
- 운전 상태가 확인된 정차 중에 준비 동의를 받습니다. Android 13 이상에서는 알림 권한을 정상 요청하며, 거절하면 준비를 시작하지 않고 이유를 표시합니다.
- ‘내비로 돌아가기’는 차록 Activity만 종료합니다. 기록 서비스는 유지합니다. 다시 차록을 열면 같은 프로세스의 같은 기록을 표시합니다.
- 순정 내비와 차량 영역은 Pleos OS가 그립니다. 확인한 배치 절차는 순정 내비를 먼저 전면에 열고, 오른쪽 창 손잡이를 왼쪽으로 끌어 **차량 / 순정 내비 / 차록** 순서로 표시하는 것입니다. 차록이 시스템 창 위치를 임의로 고정하거나 내비를 복제하지 않습니다. 알림 본문으로 재진입했을 때 OS가 차록을 넓게 여는 동작도 관측했으며, 분할은 OS 손잡이로 다시 선택합니다.

## 기록 서비스와 알림

Application이 관리하는 하나의 RecorderModel을 화면과 RecordingService가 공유합니다. 기존 직렬 작업자·Mutex·Room 저장/재조회 방식은 유지합니다. 화면의 onStop은 앱 STT를 닫지만, 사용자가 시작한 서비스가 있으면 차량 관측을 계속합니다. 정상 종료 시 서비스도 종료합니다. 저장 실패 상태에서는 미저장 내용을 재시도할 수 있도록 서비스를 유지하지만 관측은 중지합니다.

기록 준비는 화면이 보이는 상태에서만 시작합니다. Android 포그라운드 서비스 `specialUse`와 해당 권한을 선언하고, subtype에 내비 사용 중 차량 증상 기록·준비 목적을 적었습니다. 플랫폼의 해당 유형 사용 근거는 [Android foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)를 따릅니다. 스토어 심사 승인이나 실차 적합성 검증을 의미하지 않습니다.

지속 알림에는 준비 중 ‘기록 시작/준비 끄기’, 기록 중 ‘지금이야/종료·저장’을 표시합니다. 준비·시작·순간 표시·저장 결과는 별도 상태 변경 알림으로 알립니다. 알림 본문에는 증상 원문·위치가 들어가지 않습니다. 상태 알림 갱신은 1초 간격으로 병합해 Android의 과도한 알림 제한으로 최신 상태가 버려지는 문제를 방지합니다. 팝업의 실제 표시 방식은 Pleos OS와 사용자 알림 설정에 따릅니다. 알림 본문을 누른 경우에만 앱 화면을 엽니다.

서비스는 `START_NOT_STICKY`이며 부팅 수신기나 자동 재시작을 추가하지 않았습니다. 프로세스를 종료하면 수집과 마이크는 자동 재개하지 않습니다. 다음 실행에서는 기존처럼 마지막 체크포인트를 같은 ID의 중단 기록으로 복원합니다. 저장 실패 시에도 관측은 중지하고 같은 ID 재시도만 허용합니다. 종료된 서비스의 알림 액션이 새 기록을 조작하지 않도록 서비스 인스턴스별 토큰을 확인합니다.

## Gleo와 실제 입력의 구분

Gleo Action은 투명한 별도 Activity가 받아 기존 RecorderModel에 전달하고 callback 후 닫습니다. 일반 대시보드는 자동으로 열지 않습니다. [공식 schema 전달 절차](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/deliver-schema)의 Activity action filter를 유지하며 일반 런처 진입과 분리했습니다.

앱 자체의 STT는 사용자가 화면에서 명시적으로 시작하며 화면을 떠나면 닫습니다. 백그라운드 원음 녹음을 추가하지 않았습니다. 실제 Gleo 발화·STT·TTS와 Vehicle 수신은 기존 Console/VHAL 및 오디오 환경 차단과 별개로 검증해야 합니다. TEST 알림·서비스 검사가 실제 SDK 성공을 뜻하지 않습니다.
