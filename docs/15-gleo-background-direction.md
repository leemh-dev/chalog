# 차록 개발 방향 · Gleo 중심 백그라운드 기록

2026-11-15 사용자 정정에 따른 개발 기준입니다. 최초 bb872c6은 설계 문서와 이미지뿐이었으며, 후속 **31ba254 / 0.2.1**에서 선택된 A · SIGNAL 우측 패널을 구현하고 실제 크기를 검토했습니다. [SIGNAL 실행 증거](evidence/macos-pleos-signal-2026-11-15/README.md). 아래 Gleo 발화/Broadcast·자동 우측 배치는 여전히 제품 목표와 후속 검증 조건입니다.

## 시스템 구조와 차록의 역할

차록은 기본적으로 화면을 점유하지 않는 기록 서비스입니다. 운전자가 사용하는 순정 내비와 음악·콘텐츠 앱을 유지합니다. 차량정보·내비·음악 UI를 새로 디자인하거나 차록 안에서 복제하지 않습니다.

| 상황 | 화면 구성 | 차록 표시 |
| --- | --- | --- |
| 내비만 사용하는 평소 화면 | 왼쪽 차량정보 / 나머지 오른쪽 전체 내비 | 없음 |
| 콘텐츠를 함께 사용하는 평소 화면 | 왼쪽 차량정보 / 중앙 내비 / 오른쪽 음악·콘텐츠 | 없음 |
| Gleo로 기록 시작·설명·순간 표시 | 현재 화면 구성 유지 | 짧은 시스템 알림만 |
| Gleo로 기록 종료·저장 | 현재 화면 구성 유지 | 저장 확인 알림만, 이후 사라짐 |
| 사용자가 명시적으로 차록을 열기 | 왼쪽 차량정보 / 중앙 내비 / 오른쪽 차록 | 우측 앱 패널만 사용 |
| 사용자가 차록 화면을 닫기 | 이전 내비·콘텐츠 배치로 복귀하는 것이 목표 | 대시보드 숨김 |

순정 영역의 크기와 배치는 Pleos가 관리합니다. 위 우측 열기/이전 배치 복귀는 **설계 목표**이며 자동 배치 API의 실현 여부를 아직 확인하지 않았습니다. 일반 앱 시작이 primary 창을 차지하는 정책을 무시하거나, 수동 창 이동을 자동 동작의 성공으로 기록하지 않습니다. 음악 패널이 차록으로 바뀌더라도 음악을 차록이 중지하거나 불필요한 Audio Focus를 요청하지 않는 것이 목표입니다. Gleo 자체의 음성 응답/일시적인 시스템 UI는 차록 대시보드와 구분합니다.

## 발화와 동작의 구분

최초 한 번의 정차 중 준비 동의·정상 권한 설정 이후, 매 기록마다 화면의 준비 버튼을 누르도록 요구하지 않는 방향입니다. 문구는 **목표 발화**이며 실제 Gleo 인식률과 기본 앱 실행 명령과의 충돌을 검증해야 합니다.

| 목표 발화 | 기대 결과 | 대시보드 |
| --- | --- | --- |
| “헤이 글레오, 차록 켜줘” / “차록 기록해줘” | 기록 시작. 이미 기록 중이면 같은 기록 유지 | 열지 않음 |
| “기록해줘” | 차록 문맥이 확인되면 시작, 불분명하면 Gleo 확인 | 임의로 열지 않음 |
| “지금이야” / “이 순간 표시해줘” | 활성 기록에 시각 표시 | 열지 않음 |
| “회전할 때 덜컥 소리가 나” | 활성 기록에 사용자 설명 추가 | 열지 않음 |
| “차록 기록 종료해줘” / “차록 꺼줘” | 수집 중지, 같은 ID 저장·재조회, 저장 결과 전달 | 저장 후에도 열지 않음 |
| “차록 열어줘” / “차록 기록 보여줘” | 저장된 기록 또는 진행 상태 열기 | 우측 패널만 목표 |

‘켜기/기록하기’와 ‘화면 열기’를 별개의 의도로 취급합니다. 화면 열기는 새 기록을 만들지 않습니다. 기록 종료와 화면 닫기도 서로 다른 동작입니다. 권한·동의가 없으면 몰래 수집하거나 권한 화면을 자동으로 덮어 띄우지 않고 정차 후 설정이 필요하다고 응답합니다.

주행 중에는 음성으로 기록과 종료를 수행하는 방향이며, 상세 편집·보고서 내보내기 등 기존 정차/상태 확인 제한은 유지합니다. 시작 전 구간은 실제 사전 수집분이 있을 때만 포함합니다. 음성 호출로 처음 시작했다면 없는 과거 60초를 만들지 않습니다. 프로세스 종료 후 자동 수집·마이크 재개 금지, 동일 ID 복원·저장 실패 재시도 원칙도 유지합니다.

## Gleo 연동 설계

공식 App Schema는 `component: "service"`를 UI 없는 백그라운드 처리 방식으로 설명하며, 실제 전달은 `sendBroadcast()`와 `BroadcastReceiver`입니다. 이름이 service라고 해서 Gleo가 차록의 Android Service를 직접 시작하는 것으로 가정하지 않습니다. 기존 0.2의 투명 Activity 전달은 구현 이력으로 보존하고, 후속 개발에서 Broadcast 진입을 우선 검토합니다.

현재 함수 최대 3개라는 제한에 맞춘 후보는 다음과 같습니다. **이 후보 함수 구성은 아직 schema.json에 적용하지 않았습니다. 0.2.1에서는 앱 버전만 갱신했습니다.**

| 후보 기능 | component | 역할 |
| --- | --- | --- |
| CONTROL_SYMPTOM_RECORD | service | operation=start/stop으로 기록 시작과 종료 |
| ADD_SYMPTOM_EVENT | service | 사용자 설명과 순간 표시 |
| OPEN_CHAROK_RECORDS | activity | 명시적 열기 의도에만 대시보드 표시 |

함수/parameter 설명은 공식 규칙대로 간결한 영어로 작성하고, 발화 예시를 schema description에 넣거나 다른 앱 호출을 억제하는 지시를 넣지 않습니다. 각 명령은 중복 전달에 안전해야 합니다. Receiver의 발신자 신뢰 경계·권한, Android의 백그라운드 FGS 시작 조건, 실제 설치본에서의 schema 등록과 서비스 호출을 정상 경로로 확인합니다. 무음·비프·음성 Callback은 기록 결과와 함께 검토하되, 음악을 유지한다는 이유로 호출 성공/실패의 피드백을 없애지 않습니다.

## 알림과 우측 패널 디자인

- 기록 중 계속 큰 배너를 띄우지 않습니다. 시작·순간 표시·저장/실패처럼 상태가 바뀐 순간만 짧게 알립니다. 필요한 지속 상태는 Android 알림 영역에 유지합니다.
- 시안은 우측 상단의 시스템 알림을 제안합니다. OS가 허용하는 위치·수명·형식을 따르며 상단/하단 고정이나 커스텀 오버레이 권한을 전제로 하지 않습니다. 차량정보·회전 안내·음악 조작을 가리지 않는 표시를 검증합니다.
- ‘기록을 시작했어요’, ‘방금 순간을 표시했어요’, ‘기록을 저장했어요’를 구분합니다. 저장 완료는 DB 저장·재조회가 끝난 이후에만 표시합니다. 실패는 실패로 알리고 같은 ID 재시도를 유지합니다.
- 저장 결과가 앱을 자동으로 열거나 상담 카드를 자동 전면 표시하는 동작은 금지합니다. 알림 본문 클릭을 통한 자동 대시보드 진입은 기존 0.2 동작이므로 이번 방향과 맞는지 재설계합니다. 새 제품 흐름의 자동 진입 경로로 삼지 않습니다.
- 시각 개선은 **차록 우측 패널**에 집중합니다. 흰색 바탕, 분명한 제목/시간/순간 표시, 읽기 쉬운 상담 동선이 공통이며 A/B/C의 색·타이포그래피·타임라인 표현만 비교합니다. 시스템 영역의 어두운 테마는 공식 참조 화면의 것으로 차록 테마 변경 대상이 아닙니다.

[화면 흐름과 우측 패널 A/B/C](design/gleo-background/README.md)는 디자인 시안이며 실제 실행·음성 성공·SDK 성공 증거가 아닙니다. 기존 전체 대시보드를 다시 디자인한 대화 시안과 이전 상시 패널 중심 기획은 이 요구를 대체하지 않습니다.

## 구현 전 확인할 항목과 완료 기준

1. 실제 Gleo의 ‘켜줘/기록해줘’가 UI 없는 함수로 도달하고 ‘열어줘’만 화면 함수로 도달하는지 확인합니다. ‘켜줘’가 일반 런처 명령으로 해석되는 문제를 별도 기록합니다.
2. Broadcast에서 정상 권한으로 기록 서비스를 시작할 수 있는지 확인합니다. 가능한 공식 경로가 없으면 이를 차단으로 남기며 투명 Activity의 무간섭을 검증 없이 가정하지 않습니다.
3. 내비 전체 화면과 내비+음악 분할에서 시작/표시/설명/종료를 각각 검사합니다. 각 단계 전후 창의 위치·크기·내비 경로·음악 재생 상태가 유지돼야 합니다. 저장 후에도 차록 Activity가 나타나지 않아야 합니다.
4. 명시적 열기에서 순정 내비를 유지하며 오른쪽 콘텐츠만 차록으로 바꾸는 공식 창 경로를 확보합니다. 닫기 후 이전 배치도 확인합니다. 현재 공개 Window Policy는 임의의 우측 고정을 보장하지 않으므로 이 부분을 별도 기술 검증 과제로 둡니다.
5. TEST, 실제 Gleo 발화, 실제 SDK 관측, 알림, 순정 내비 안내·음악 유지의 성공을 각각 기록합니다. SDK 환경 차단이 해결되기 전 시안이나 Intent 직접 주입을 실제 음성 성공으로 바꾸어 표시하지 않습니다.

최초 설계 단계에서는 빌드·기기 실행을 하지 않았습니다. 후속 SIGNAL UI 실행 결과는 위 별도 증거에 있으며, 다음 Gleo 개발은 이 문서의 사용자 의도와 완료 기준을 따르고 기존 DB·변경을 보존합니다.
