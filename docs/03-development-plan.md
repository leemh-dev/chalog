# 차록 개발·검증 계획

2026-11-14 UTC · 현재 단계: **기획 완료 초안 / 구현 미착수**

> 단계0은 [전체 시나리오 재검토05](05-conversation-scenario-feasibility.md)의 실제 Gleo3명령/asking·시스템 분할·구간 버퍼를 우선 검증한다. 원음 출력/정식 예약은 지원 근거 전까지 차단/미검증이며 실제 성공으로 연출하지 않는다.

목표는 Pleos에서 구간 기록부터 고객·정비사 검토까지 실제 앱으로 시연하는 것입니다. 날짜만으로 단계 완료를 선언하지 않습니다. 구현은 새 요청 이후 시작하며 이번 문서 작업에 앱 개발을 포함하지 않습니다.

## 단계0 · 작은 SDK 실행 검증

Cloud에서 최소 Kotlin Android 프로젝트와 공식 STT ON_DEVICE/Vehicle 연결을 준비합니다. 컴파일·초기화·권한·값 수신·callback 중단을 나눠 기록합니다. PRIVATE API는 사용하지 않습니다.

Mac Pleos에서 한국어 PCM 입력과 실제 마이크 입력을 각각 시험합니다. 주행거리와 관련 상태 한 가지 이상을 실제로 수신합니다. Gleo 시작/종료 호출은 STT 성공과 분리합니다. 위치가 필요하면 지원 여부·권한·새 callback을 별도 시험합니다.

**통과 문턱:** 공식 STT 최종 텍스트 + 공개 Vehicle 값/수신 시각. APP_TEST만 통과하면 SDK 연동 완료가 아닙니다. 필요한 상태를 확보하지 못하면 UI 대량 구현 전 범위를 재평가합니다.

## 단계1 · 구간 기록과 복원

Cloud에서 명시 준비→60초 순환 버퍼→동일 session ID의 기록→사용자 종료→SQLite 저장ACK를 구현합니다. callback/발화/명령 결과의 시각과 공백을 보존합니다.

검증은 준비0초/20초/60초 이상, 두 번 시작/종료, 음성 처리 지연, SDK 끊김/권한 철회, 시간 변경, 종료 명령 실패, 연속 세션, 저장 실패/용량 부족, 프로세스 종료·새 PID 복원입니다. ON_STOP/앱 종료 처리와 자동 재개 방지는 지원되는 실행 모델에 맞춰 확인합니다.

**통과 문턱:** DB 실제 재조회로 구간 경계/관측/원문/중단 사유가 일치합니다. 화면 표시만으로 저장 성공을 판단하지 않습니다. 재시작 후 과거가 없으면 공백으로 표시합니다.

## 단계2 · 고객 화면과 증상 정리

준비·기록 중·저장 결과를 큰 상태 중심으로 표현합니다. 정차 후 타임라인/원문 수정/반복 기록 묶기를 제공합니다. 주행·상태 미확인에서 상세 조작을 제한합니다.

요약은 원문과 분리하고, 센서 값과 사용자 표현을 혼동하지 않습니다. 서로 다른 증상 과도 병합, 무음/부분 결과/오인식/취소를 확인합니다.

**통과 문턱:** 출처와 공백을 화면에서 구분하고 원문을 열 수 있습니다. Gleo/버튼/TEST 진입을 표시합니다. 순정 분할 자동 제어가 없어도 앱 흐름은 완결됩니다.

## 단계3 · 정비사 열람과 상담

선택 구간의 한 장 요약과 타임라인을 만듭니다. 보고서/PDF 저장 및 실제 공유 대상 존재를 확인합니다. QR/웹뷰어를 도입하면 고객 동의·만료·취소/접근 통제·네트워크 실패를 구현합니다.

고객 발화·SDK 관측·환경 자료·정비사 진단의 출처/시각을 나눕니다. 실제 스캐너 DTC를 못 가져오면 미연결로 표시하고 필요 시 명시된 TEST 자료만 사용합니다.

**통과 문턱:** 고객이 선택한 한 건을 실제 다른 단말에서 열어 상담할 수 있습니다. GDS 내부 조회와 별도 뷰어를 구분합니다. 스캐너 자동 연동은 정식 지원 확인 전 미검증입니다.

## 단계4 · 전체 시연과 효용 확인

실제 앱에서 준비→직전 구간 확보→음성 시작→상태 변화→종료→저장→정비사 열람을 촬영합니다. 녹화 중 Console/PCM/TEST/실제 마이크/SDK 수신을 각각 표시합니다. UI 합성을 실제 Pleos 실행처럼 제시하지 않습니다.

정비사에게 자유 설명과 기록 요약을 비교해 추가 질문·누락 조건·과장/왜곡을 확인합니다. 인터뷰가 없다면 효용은 가설로 남깁니다. 전체 운행 기록·모든 고장 진단·스캐너 자동 연결을 시연에서 약속하지 않습니다.

## 단계5 · 정식 스캐너 연동 확장

GDS/GIT/현대 측 지원 경로가 확인된 경우에만 추진합니다. 접수건/차량 연결·동의·권한·기록 포맷·시간축 계약을 정하고 실제 스캐너 연결 후 조회를 시험합니다. 공개 API 없는 상태에서 OBD/ECU에 앱 기록을 노출하는 우회 개발을 하지 않습니다.

이 단계는 장기 목표이며 최초 기능 검증/시연 완료와 분리합니다.

## Cloud와 Mac 작업 원칙

| 환경 | 역할 | 실제 확인할 항목 |
| --- | --- | --- |
| Cloud | 구현·정적 분석·단위/저장 검사·빌드·문서·GitHub 기록 | 코드/로그/버전/APK 해시/서명 종류 |
| Mac M1·8GB + 외장SSD | Pleos 에뮬레이터 한 대에서 실행 | ADB 준비, SDK/마이크/Gleo/Console/실제 화면 |

Mac에서는 저장소·SDK/AVD·캐시를 가능한 외장SSD에 두되 Android 도구/OS 동작에 필요한 내부 사용까지 0으로 보장하지 않습니다. 환경을 조사한 뒤 실제 설정 명령을 문서화합니다. Cloud 빌드 전달로 중복 자원 사용을 줄입니다.

기기 설치 전 transport=device, boot 완료, package/activity 서비스와 각 종료 코드를 확인하고 설치 직전에 다시 조회합니다. 기존 앱 데이터 삭제·키 복사·인증 우회·근거 없는 부팅 반복은 하지 않습니다. 미연결 Mac에서 실행했다고 기록하지 않습니다.

## 진행·증거 기록

- 단계별 완료/진행/차단/미검증과 다음 확인을 공유합니다. 임의 진행률을 만들지 않습니다.
- 앱이 실행되면 최초 화면/주요 전환/오류·수정 전후를 실제 캡처해 중간 공유합니다. 이전 이미지를 새 캡처로 쓰지 않습니다.
- 문서 확인, 컴파일, 단위 테스트, 일반 Android, Pleos SDK, Console 조작, 실차를 구분합니다.
- 기능별 브랜치·커밋·푸시·PR로 기록하고 자동 병합하지 않습니다. 초기 기획 문서는 빈 저장소 main의 최초 커밋으로 둡니다.
- APK 생성 시 코드 커밋·버전·SHA-256·개발서명/unsigned를 기록합니다. 앱마켓 출시 서명은 초기 범위 밖입니다.
- 개인정보·차량 식별자·실제 이동 경로·비밀값을 공개 GitHub/로그/artifact에 남기지 않습니다.
