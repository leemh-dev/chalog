# 기록에서 관측한 경고·표시등

0.2.2/4에서 SIGNAL 기록 요약과 정비 상담 카드에 경고·표시등을 추가합니다. 계기판을 복제하는 상시 경고 화면이 아니라 **해당 기록 구간에 수신한 이력**입니다. 앱을 자동으로 열거나 새 오버레이·경고음으로 내비/음악을 방해하지 않습니다.

## 표시와 저장

- 엔진·타이어 공기압 등 수신한 항목의 이름, 최초 관측 시각/기록 시작 대비 시각, TEST 또는 SDK 출처, 마지막 확인 상태를 표시합니다. 요약은 최대3종, 상담 카드는 전체 항목입니다.
- `ON`은 점등, `BLINK`는 점멸, 명시적으로 수신한 `OFF`만 소등으로 표시합니다. 점등 후 소등돼도 기록에서 지우지 않습니다. 최초 관측 시각은 실제 점등이 시작된 시각과 같다고 가정하지 않습니다.
- 조회 실패·응답 지연·이후 스냅샷에서 항목 누락은 상태 미확인으로 처리합니다. 데이터 없음 / 조회 실패 / 수신 항목의 점등 기록 없음을 구분하며, 이 중 어느 것도 차량 전체가 정상이라는 판정은 아닙니다.
- 기존 Observation의 field/value/source/수신 시각을 사용하므로 Room/JSON 스키마와 기존 DB는 그대로 유지합니다. 선택 보고서에 같은 요약과 원시 관측을 넣습니다.
- 준비 버퍼에 실제 들어온 경고는 기록 시작 전 상대 시각으로 표시합니다. 기록 종료·재실행 뒤 자동 조회/수집을 시작하지 않습니다. 주행/현재 운전 상태 미확인 때는 상세 표시 제한을 유지합니다.
- 엔진·타이어 아이콘과 황색 강조는 항목 식별용 앱 디자인입니다. 실제 계기판의 색상·우선순위나 고장 심각도를 추론하지 않습니다. 알 수 없는 표시등 타입은 SDK 이름을 보존합니다. DTC·고장 원인·소음 자동 진단 기능이 아닙니다.

## SDK 경로

공식 [Safety.getTelltalesInfo](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/safety/get-telltales-info)와 현재 고정한 Vehicle2.3.2의 배포 AAR 시그니처/권한 annotation을 대조했습니다. 웹 API 본문이 비어 있는 부분은 바이너리의 선언을 기준으로 구분했습니다.

- 공개 getter는 `CAR_SAFETY`가 필요합니다. manifest에 선언하고 정상 권한이 있는 경우에만 호출합니다. 거부/서비스 미지원/오류는 미수신입니다. 앱마켓 승인이나 실제 차량 지원을 보장하지 않습니다.
- `checkTelltalesCapabilities`와 `registerTelltales`는 `PRIVATE_CAR_SAFETY`여서 사용하지 않습니다. private 권한을 선언하거나 인증을 우회하지 않습니다.
- 준비/기록 중 최대5초 간격의 스냅샷 조회입니다. 연속 ECU 이벤트가 아니므로 조회 사이의 짧은 점멸이나 모든 상태 변화를 보장하지 않습니다. callback에 실제 센서 시각이 없으므로 수신 시각을 저장하고 sampleAt은 미제공으로 유지합니다.
- 점등/점멸 항목은 매 성공 조회에서 보존하며, 점등되지 않았던 OFF 항목은 경고 이력으로 추가하지 않습니다. 명시적 소등 변화와 미수신은 별도 보존합니다. 조회 세대가 바뀌거나 수집을 끝낸 뒤의 늦은 callback은 버립니다.

## 검증 기준

단위 검사에서 반복 점등 집계, 소등 이력 유지, 누락/실패의 미확인 처리, TEST/실제 출처 분리, 준비 구간, JSON/보고서 보존을 확인합니다. 기기 검사에서는 TEST 점등→소등→같은 ID 저장→화면 재생성→상담 카드·보고서를 확인합니다. 기존 기록은 업데이트 전후 payload 전체를 대조합니다.

실제 SDK 경고 수신은 별도 검증 대상입니다. TEST 엔진/타이어 버튼이나 Intent 주입을 실제 차량 성공으로 표시하지 않습니다. 영상은 이번에도 제작하지 않으며 실제 Pleos 스크린샷과 실행 결과는 docs/11의 최신 증거를 따릅니다.
