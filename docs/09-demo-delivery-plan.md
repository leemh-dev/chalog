예상 시간은 일정 계획이며 완료 보장이 아닙니다. 마감 직전 기능 추가보다 서명한 필수 접수양식과 검증된 자료를 먼저 확보합니다. 새로운 앱 구현은 별도 실행 작업이며 이번 기획/디자인 결과를 구현 성공으로 표시하지 않습니다.

## 개발을 시작할 때의 최소 구현 순서

1. TEST와 SDK가 같은 RecordEngine을 쓰되 source가 섞이지 않도록 모델을 정의합니다. Session, Observation, SymptomNote, Bookmark, ExportManifest를 같은 ID에 연결합니다.
2. 준비0/20/60초, 중복 시작/종료, 시간 변경, 관측 누락을 단위 검사합니다. 정적 가짜 과거를 실제 수신 버퍼로 세지 않습니다.
3. SQLite checkpoint·최종 commit·재조회·새 PID 복원을 시험합니다. 저장 실패는 동일 세션 재시도, 수집은 재시작 후 OFF입니다.
4. 좁은/넓은 앱 패널에 같은 상태를 바인딩합니다. 운전 상태 미확인 시 상세 잠금, 한 질문·짧은 피드백을 적용합니다.
5. 실제 기기 접근 시 ADB transport/boot/package/activity·각 rc를 확인하고 설치 직전에 재확인합니다. 새 전용 AVD를 사용하고 기존 데이터/인증 키를 바꾸지 않습니다. Mac SDK/AVD·저장소는 가능하면 외장SSD에 두고 M1 8GB에서 AVD 한 대만 실행합니다.
6. SDK 한 필드 수신, Gleo 함수와 실제 마이크 STT를 개별 확인합니다. Gleo가 막히면 앱 내 STT 또는 표시된 TEST 입력으로 남기고 성공 범위를 낮춥니다. 연결 불가 환경에서 같은 부팅을 반복하지 않습니다.
7. 선택된 보고서를 내보내고 다시 읽어 원문·관측·누락·공유 범위가 일치하는지 확인합니다. 실제 센터 정보와 NaviHelper를 확인할 때만 길 안내 화면을 추가합니다.

## 시연 영상 · 90~120초 제안

| 구간 | 보여줄 경험 | 근거/자막 |
| --- | --- | --- |
| 0~10초 | “정비소에 오니 소리가 안 나요”라는 문제 | 연출된 사용자 상황 |
| 10~25초 | 기록 준비·실제 확보 구간 | 준비0/20/60초 중 실제 값, 출처 배지 |
| 25~45초 | 증상 시작·한 질문·설명 | Gleo/실제 마이크/PCM/TEST 중 실제 수행 방식 표시 |
| 45~60초 | “지금이야” 순간 표시·종료 | 사용자 표시, 소음 감지 아님 |
| 60~80초 | 저장 완료·정차 후 요약 | 앱 영상이면 실제 DB 저장 증거 필요 |
| 80~100초 | 고객·정비사가 같은 기록 열람 | 실제 생성 파일/별도 뷰어 여부 명시 |
| 100~120초 | 확인된 내비 연결 또는 발전 계획 | 실행 못한 예약/원음/GDS는 ‘향후 연동’ 별도 화면 |

차량 정보+내비+차록의 목표 배치를 시안으로 설명할 수 있지만 실제 Pleos 영상과 혼합해 실행 성공처럼 보이게 편집하지 않습니다. 시안 영상에는 지속적으로 ‘UX 프로토타입·TEST’를 표시합니다. 실제 실행 영상은 환경/코드/APK/입력 출처를 남깁니다. 실제 확보한 앱 화면은 중간에도 채팅에 공유합니다.

## 제출 수준의 문턱

- **오늘 확정할 수 있는 산출물:** 공식 양식의 기획 내용과 디자인 시안. 개인 정보·서명은 작성자 본인이 채워야 합니다.
- **프로토타입 영상:** 이번 HTML을 촬영하면 UX 목업 영상입니다. 공식 제출 안내가 목업을 허용하지만 Android/Pleos 앱 영상은 아닙니다.
- **앱/소스+APK:** 실제 구현·빌드·설치·흐름 검사 후에만 제출 수준으로 표시합니다. 실행 가능한 release에 서명해야 하며 unsigned는 설치용 제출본으로 세지 않습니다. 개발/테스트 서명과 앱마켓 출시 서명을 구분합니다.
- **외부 통합:** 원음·실제 예약·GDS는 공개 지원/제휴와 실제 성공 증거가 있기 전까지 제외합니다. API 부재를 가짜 완료 화면으로 메우지 않습니다.
